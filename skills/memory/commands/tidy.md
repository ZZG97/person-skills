# Tidy Persistent Information

Read the Home's information architecture and indexes. Inspect detailed files only
where ownership, duplication or freshness is in question.

- Follow [the common update workflow](update.md) when moving facts or matter state.
  Merge into an existing owner; preserve evidence and original as-of times.
- Migrate a legacy matter's status and actions to one item, verify it by reading
  back, then leave an item reference in the old location. Retain useful background
  and history with an explicit snapshot date. Do not keep a live status copy.
- An index may list priority and owner references. Remove copied deadlines, status
  and next-action prose; the ledger renders those views.
- Keep raw uploads, generated artifacts and project documentation with their own
  owners. Remove empty taxonomies only when they are genuinely unused.
- Preserve unrelated changes. Summarize any material move, deletion or redaction
  and run the Home's context renderer when its always-loaded router changed.
