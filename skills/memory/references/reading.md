# Reading memory and matters

Use the Home's short memory router to find preferences, system facts, project context
and knowledge. Read the narrowest authoritative file; do not load all memory files.

For tracked matters:

- Open/awaited work: `DATA/views/index.md`; active and waiting are to-dos, observe is
  watch-only. Do not read `items/` wholesale.
- One matter: `DATA/views/items/<item_id>.md`, including its disposition reason,
  evidence, next actions, follow-up, events and gaps. Follow linked background only
  when needed. A transferred pointer delegates status to the referenced tracker.
- Checks, decisions, nudges and deadlines: `DATA/views/followup.md` or
  `pledger followup-report`.
- People: `DATA/views/people/index.md` and an individual page.
- Problems: `DATA/views/lint.md`; inspect events before acting on an old next action.

Give the as-of time when freshness matters. Historical journals and legacy snapshots
can explain a decision but do not override the item's current disposition.
